# NOTES — assumptions & decisions made during the build

Recorded per the build spec: ambiguities were resolved with the most
sensible assumption for a privacy-first consumer product, and anything that
would otherwise have meant silently adding a dependency, permission, or
out-of-tree file is flagged here.

## Project layout
- **Repo root = `susurro/` project root.** This repository is dedicated to
  the app, so the structure from the spec lives at the repository root
  instead of a nested `susurro/` directory.

## Dependencies (kept to the locked stack)
- Runtime/dev dependencies are exactly: `electron`, `electron-builder`,
  `vue`. Nothing else.
- **No native automation node module** (`nut.js` is commercial, `robotjs`
  unmaintained/ABI-fragile). The spec's "robotjs-equivalent" is implemented
  with each OS's own automation layer invoked as a subprocess:
  - macOS: `osascript` → System Events `keystroke` (covered by the same
    Accessibility permission a native library would need)
  - Windows: PowerShell → `System.Windows.Forms.SendKeys`
  - Linux/X11: `xdotool` · Linux/Wayland: `ydotool`/`wtype`
  Same capability, zero native build steps, and dictated text is passed via
  argv/environment — never interpolated into a shell string.
- **Vue without a bundler.** The prebuilt `vue.global.prod.js` is copied
  into `src/renderer/assets/vendor/` on `npm install` (see
  `scripts/copy-vue.js`); renderer pages are plain HTML + JS. Smallest
  possible bundle, no build pipeline. Consequence: the renderer CSP includes
  `'unsafe-eval'` because Vue's in-browser template compiler uses
  `new Function`; `default-src 'self'` still blocks all remote code/content.

## STT engine
- **Python is not bundled.** Bundling a Python runtime per-OS would triple
  installer size; the spec allows documenting a one-time local install
  instead, which `SETUP.md` does (`pip install faster-whisper`). The app
  probes `python3`/`python` and supports a `pythonPath` settings override.
- Models download from the `Systran/faster-whisper-*` Hugging Face repos —
  the only network endpoint the app ever contacts — into
  `<userData>/models/<name>/`, marked complete with a `.complete` marker
  file. faster-whisper is invoked with `local_files_only=True` so it can
  never fetch anything itself.
- Transcription runs `device=cpu, compute_type=int8` for universal
  compatibility. GPU users can still benefit later without config changes
  being required for correctness.
- Audio is captured in the overlay renderer at 16 kHz mono, converted to
  16-bit PCM WAV in the main process, handed to the subprocess by file path,
  and the temp WAV is deleted after each transcription.

## Injection details
- Wayland fallback ladder (auto mode): ydotool (daemon verified) → wtype →
  clipboard + paste chord via xdotool (works for XWayland apps) → clipboard
  + notification asking the user to press Ctrl+V. The one-time explanatory
  note fires the first time the fallback path is actually used.
- Clipboard paste preserves the previous clipboard text and restores it
  ~1.2 s later, unless something else claimed the clipboard meanwhile or the
  manual-paste path is active (text must stay pasteable).
- The overlay window is `focusable: false` so tapping it never steals focus
  from the app being dictated into.

## Design tokens
- Fraunces/Inter are declared via `@font-face` pointing at
  `src/renderer/assets/fonts/*-Variable.woff2` with serif/system fallbacks.
  Font binaries are **not** vendored (no network fetch at build or runtime;
  redistribution best handled by the developer dropping in the OFL files).
  The UI renders correctly with the fallback stacks in the meantime.

## Packaging / releases
- `releases/` is generated by `scripts/generate-release-manifest.js`, which
  hashes whatever installers exist in `dist/` and lists not-yet-built
  platform artifacts with `status: "pending"` and null size/checksum so the
  JSON shape the marketing site consumes is always complete. Installers can
  only be produced on their native OS (mac artifacts require macOS, MSI
  requires Windows), so a fresh clone regenerates the manifest after running
  the per-OS `npm run dist:*` builds.
- The committed manifest in `releases/` was generated in the build
  environment used for this session, whose network proxy blocked downloading
  the Electron runtime binary — so **all six artifacts are `pending`** until
  `npm run dist:*` is run on real macOS/Windows/Linux machines, followed by
  `npm run release:manifest`.
- **`.github/workflows/release.yml`** (added after the initial build, not in
  the original file structure) automates exactly that: a 3-OS build matrix
  (macos-latest/windows-latest/ubuntu-latest) each running its
  `npm run dist:*` script, followed by a publish job that collects every
  artifact, runs `release:manifest`, and creates a GitHub Release with the
  installers plus `releases.json`/`RELEASES.md` attached. Triggered by
  pushing a `v*.*.*` tag, or manually via workflow_dispatch. Flagged here per
  the spec's "stop and flag before adding files outside `susurro/`" rule —
  `.github/` is repo tooling, not part of the app itself, and is the only
  way to actually produce all three installers since this sandbox's egress
  policy blocks the Electron binary download needed to build even one.
  No code-signing secrets are configured, so the mac/Windows builds this
  workflow produces are unsigned (matches the "signing is optional for local
  use" note already in `electron-builder.yml`/`SETUP.md`); add
  `CSC_LINK`/`CSC_KEY_PASSWORD` etc. as repo secrets to sign real releases.
- Icons are generated programmatically (`scripts/generate-icons.js`, raw
  PNG encoder, no dependencies) and committed; electron-builder converts
  the 512 px PNG to `.icns`/`.ico` at package time.
- **Fixes found by actually running the release workflow** (run #1, all three
  platforms failed on first attempt — logs pulled via the GitHub API):
  - `publish: null` added to `electron-builder.yml`. Without it,
    electron-builder auto-detects the GitHub remote under `CI=true` and
    tries to check for a draft release to publish to, which fails any build
    job lacking `GH_TOKEN` (build jobs intentionally don't have one —
    publishing is the separate `publish` job's responsibility, via
    `softprops/action-gh-release`, not electron-builder's own publish path).
  - `mac.target[*].arch` changed from `[x64, arm64]` to `[universal]`.
    Building both archs for the `pkg` target concurrently raced on a shared
    intermediate filename inside electron-builder and reliably failed
    (`ENOENT` on cleanup). A universal binary avoids the race and ships one
    download that runs natively on both Intel and Apple Silicon instead of
    two separate ones — `@electron/universal` is already a transitive dep of
    electron-builder, so this needed no new dependency.
  - `linux.maintainer` set explicitly (placeholder `noreply@susurro.dev`).
    The `.deb` target refuses to build without a maintainer email, and
    `package.json`'s `author` field is a plain string with none. Replace
    with a real support address if you want it discoverable via
    `dpkg -s susurro`.

## Behavior clarifications
- "Start/Stop Listening" in the tray, the global hotkey, the overlay click,
  and the main-window button all funnel into the same toggle.
- Toggling while a transcription is in flight is ignored (state machine:
  idle → recording → transcribing → idle).
- Recordings shorter than ~250 ms are discarded silently.
- The Ollama cleanup guard rejects responses that change the text length by
  more than 2×/0.3× — cleanup is only ever grammar/filler removal, so a wild
  change means the model misbehaved and the raw transcript is used instead.
- Onboarding step 2 is skippable ("Continue" always enabled) because on
  Windows/X11 there is nothing to grant, and on macOS the user may prefer to
  grant Accessibility later; dictation still works and the injection layer
  reports errors gracefully.
- History stores text + timestamp only; no audio is ever persisted.
